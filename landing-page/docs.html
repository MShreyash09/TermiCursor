Intro

TermiCursor is an AI coding agent that runs on your machine. Give it a task and it plans the work, edits files, searches your code and runs commands, asking before anything risky. It uses local models through Ollama by default, so your code stays on your PC.

There are two ways to use it, both backed by the same agent:

  • Desktop app: editor, file tree, terminal and agent panel in one window.
  • Terminal app: the termicursor command.

Install

First install Ollama and make sure it's running. Requirements: Windows 10/11, 8 GB RAM recommended.

Desktop app

Download the installer from the latest release and run it. The app updates itself from GitHub.

Terminal app

Needs Python 3.10 or newer.

pip install git+https://github.com/MShreyash09/TermiCursor.git

First run

  1. Open TermiCursor. The status bar turns green and shows ready once it can reach Ollama.
  2. If it shows Models missing, click Install. The default models (qwen2.5-coder:3b and nomic-embed-text) are about 2.2 GB. Or pull them yourself: 
    ollama pull qwen2.5-coder:3b
ollama pull nomic-embed-text
  3. Open a project folder. It gets indexed for search in the background.
  4. Type a task in the agent panel, for example "add a /health route to server.py".

Keep your project in git so every change is easy to review and undo.

Modes

Switch with tab in the terminal, or the mode switch in the app.

ModeWhat it does
AskAnswers questions. Read-only tools only: it can open and search files, but can't edit or run commands.
PlanWrites a step-by-step plan and stops. Edit steps, ask for changes, approve or reject. Nothing is written until you approve.
BuildPlans when the task needs it, then edits files, runs commands and checks the result.

Terminal app

Run it inside your project folder:

cd my-project
termicursor
Key / commandAction
tabCycle Build / Plan / Ask
/build /plan /askPick a mode directly
/modelChoose the model
/clearClear the screen
/helpList commands
/exitQuit (/quit works too)

Approvals

The agent pauses and asks you before it:

  • runs any shell command,
  • deletes a file,
  • writes outside the project folder.

Settings → Auto-approve shell commands skips the prompt for commands, except destructive ones (rm, del, git reset --hard…), which always ask. You can stop a run at any time.

Tools

The agent works one tool call at a time. You see each call as it happens.

ToolPurpose
grep, find_files, list_dirFind files and text
search_codebaseSearch the project by meaning (falls back to text search if not indexed)
read_fileRead a file, 200 numbered lines per page
edit_file, write_file, delete_fileChange files
run_shell_commandRun builds, tests, scripts
browser_navigate, browser_click, browser_get_textTest web apps in Edge. Each session is recorded to a video in Artifacts.

Models & providers

Pick the provider and model in Settings (or /model in the terminal). Changes apply on the next request, no restart needed.

  • Ollama (default): any model you've pulled. Everything stays local.
  • Groq: faster cloud inference. Needs an API key.
  • Custom: any OpenAI-compatible API (name, base URL, key, model).

With Groq or a custom provider, your prompts and the code the agent reads are sent to that provider.

Pick a model for your PC

Bigger models write better code but need more memory. If a model doesn't fit, replies crawl or Ollama fails to load it. What matters is the memory that holds the model: VRAM on a supported GPU (fast), otherwise system RAM (works on any modern CPU, but slower).

ModelDownload[2]Memory used[3]Recommended PC
qwen2.5-coder:1.5b1.0 GB~1.2-1.5 GBUnder 8 GB RAM, no GPU. Simple edits only.
qwen2.5-coder:3b (default)1.9 GB~2.1-2.5 GB8 GB RAM, or a 4 GB GPU
qwen2.5-coder:7b4.7 GB~5.4-5.5 GB16 GB RAM, or an 8 GB GPU
qwen2.5-coder:14b9.0 GB~9.8-9.9 GB16-32 GB RAM, or a 12 GB+ GPU
qwen2.5-coder:32b20 GB~18.7-18.9 GB32 GB+ RAM, or a 24 GB GPU

Install one with ollama pull <model>, then pick it in Settings or with /model.

How these numbers were chosen

  • Ollama's own guidance: "You should have at least 8 GB of RAM available to run the 7B models, 16 GB to run the 13B models, and 32 GB to run the 33B models."[1] That's RAM available, so on top of Windows and your other apps.
  • "Memory used" is Qwen's measured footprint for 4-bit versions of each size[3], which is what Ollama downloads by default[2]. The GPU column adds headroom for context, since the model has to fit in VRAM entirely to run at full speed.
  • Example: with 8 GB RAM and no big GPU, 3B runs fine but 7B (~5.5 GB) leaves too little for Windows, so it swaps and stalls.

Does my GPU count?

Ollama uses[5]:

  • NVIDIA: compute capability 5.0+ (GTX 900 series and newer) with driver 550 or newer.
  • AMD on Windows: Radeon RX cards on the supported list (e.g. RX 7900 XTX / XT) with a ROCm-capable driver. Others may work through Vulkan.
  • Intel / integrated graphics: at most via Vulkan. Plan on the RAM column instead.

Is it too big?

  • Run ollama ps while it answers. The PROCESSOR column shows 100% GPU (all in VRAM), 100% CPU (all in RAM), or a split like 48%/52% CPU/GPU[4]. A split or 100% CPU on a GPU machine means the model is too big for your VRAM: drop one size.
  • Out-of-memory errors, a frozen PC, or a first reply that takes over a minute all mean the same.
  • Switching is instant, no restart needed.

Can't run anything above 3B? Use a Groq or custom provider for bigger models (see above), knowing your prompts and code are sent to them.

Settings file

The Settings page writes settings.json in the data folder (see below). You can also edit it by hand:

{
  "llmProvider": "ollama",
  "ollamaModel": "qwen2.5-coder:3b",
  "ollamaUrl": "http://localhost:11434",
  "groqApiKey": "",
  "groqModel": "llama-3.1-8b-instant",
  "autoApproveShell": false
}

Environment variables LLM_PROVIDER, OLLAMA_URL, OLLAMA_LLM_MODEL, GROQ_API_KEY and GROQ_MODEL are used when a setting is empty.

Where data lives

Everything is stored locally in %LOCALAPPDATA%\Termicursor\Termicursor (override with the TERMICURSOR_USER_DATA environment variable):

  • settings.json: your settings
  • local_qdrant\: the search index, one collection per project
  • artifacts\: command logs and browser recordings

Desktop app logs: %APPDATA%\Termicursor\logs\main.log.

Troubleshooting

Status bar says Ollama isn't reachable

Start Ollama (open the app, or run ollama serve) and check it answers at http://localhost:11434. If it runs elsewhere, set ollamaUrl.

Models missing

Click Install in the status bar, or run the ollama pull commands from First run.

Answers are slow or low quality

The default 3B model is chosen to run on most PCs. If you have the RAM/GPU, pull a bigger coder model and select it in Settings, or switch to Groq.

Something else

Open an issue and attach main.log. Security problems: see SECURITY.md.
